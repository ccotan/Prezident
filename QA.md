# Проверка обновления 3

## Автоматически в Chromium — локальное демо

- Гостю недоступны отчёты, задачи, кабинет, состав и журнал; отчёты не отрисовываются в скрытом DOM.
- Markdown-отчёты с изображениями, подписью и редактированием без дубликата.
- Мин. Эко. видит только свой переключатель и свои отчёты. Подстановка чужого channel в интерфейсе сбрасывается; чужие добавление/удаление в демо отклоняются.
- Глава принимает свободного игрока только в своё министерство; не меняет чужих глав и не использует role_set.
- Президент ставит задачу, министерство отправляет результат с отчётом на проверку. Принять задачу министерство не может; Президент может. Чужое министерство не видит задачу.
- Автор жалобы добавляет сообщение и ссылку-доказательство. Мин. Без. выносит решение с причиной; появляется системное сообщение в переписке. Другой министр открыть жалобу не может.
- Указ имеет номер, отменяется с причиной; поиск и фильтр действующих/отменённых работают.
- Кабинет показывает профиль; уведомления отмечаются прочитанными; журнал содержит события действий.
- Все 14 маршрутов проверены при 1460 и 390 px, горизонтального переполнения страницы нет. Таблица ролей имеет собственную горизонтальную прокрутку.
- Нет pageerror в проверенных сценариях.

## Визуальная проверка

Просмотрены по отдельности десктопные и мобильные снимки всех маршрутов, редактора отчётов и переписки по жалобе. Исправлены контраст переключателей каналов, отступы формы набора игроков. Редактор и длинные диалоги прокручиваются внутри окна; кнопка отправки отчёта остаётся видимой. Дополнительно выполнен bundled capture helper: без JS-исключений и горизонтального переполнения главной.

Для воспроизводимости тесты подменяют внешние головы и тестовое фото локальными изображениями. В поставляемом сайте подмена отсутствует: используется mc-heads.net. Без интернета показывается предусмотренная локальная запасная голова.

## Серверный режим — имитация HTTP API

Проверяет формат запросов и UI, **не выполняет SQL и не доказывает корректность RLS**:
- Логин и загрузка таблиц, включая новые таблицы V3.
- Загрузка PNG в Storage с токеном, публикация/обновление новости.
- Раздельные запросы черновика и публикации закона.
- report_add с channel/images и report_update без дубликата.
- task_save с полями задачи.
- Ошибка сети не включает демо и не сохраняет серверные реестры в localStorage.

## Что НЕ проверено здесь

SQL-миграция на настоящем PostgreSQL/Supabase, RLS и RPC на настоящих аккаунтах, реальные Storage/SMTP, публикация GitHub Pages/Actions, буфер обмена в браузере пользователя и доступность реальных Minecraft-голов. Эти пункты необходимо пройти после развёртывания по README.

Сайт не опубликован в GitHub пользователя; реальная база не изменялась. В архиве — исходники, полная схема для нового проекта, миграции и инструкции.

Фактическая загрузка Comfortaa в этой офлайн-среде недоступна, поэтому визуальная проверка именно этого начертания не заявляется. SQL и логика V3 не изменялись.

## Чат по жалобе — последняя доработка

- Вместо модального окна: отдельный маршрут #case/<id>. Проверено настоящим нажатием «Открыть обращение» в списке, не только вызовом функции.
- Автор отправляет сообщение с фото; после перезагрузки прямой ссылки переписка доступна при сохранённом демо-входе.
- Мин. Без. отвечает и меняет статус; история содержит сообщения и системную запись.

- Настоящая RLS/SQL, межпользовательский обмен на Supabase и реальные сетевые сервисы здесь не проверены. Периодическое обновление — опрос раз в 10 секунд, а не WebSocket/push.

## V4.4 — настоящая OAuth identity Discord

### Функциональность и защита
- Ручной контакт заменён на Supabase Auth identities. Проверенный статус не берётся из legacy profile_contacts, локальных демо-данных или редактируемого user_metadata.
- На имитации Supabase/Discord проверены авторизованный GET /user/identities/authorize, provider=discord, skip_http_redirect=true, PKCE verifier/challenge SHA-256, фиксированный redirect портала, обмен code на сессию и проверка того же user ID через /auth/v1/user.
- После callback сохраняются исходные Minecraft-ник, министерство и должность. Проверены перезагрузка и отвязка выбранной identity без удаления профиля, почты или прав.
- Проверены отмена, отключённый Manual Linking, недопустимый URL редиректа, отсутствие временного PKCE-запроса, истёкший запрос, callback с user ID другого аккаунта и смена аккаунта в ходе потока. Несовпадающая сессия не записывается поверх исходной.
- Проверены ошибка отвязки и запрет отвязки без подтверждённой email-identity. Финальное решение о допустимости операции принимает Supabase Auth.
- Тестовые provider_token/provider_refresh_token из ответа не попадают в localStorage. OAuth code и временный verifier очищаются после обработки; выход из аккаунта также отменяет временный запрос. Добавлен meta referrer=no-referrer.
- В автономном демо кнопка не выполняет OAuth и не подменяет настоящий подтверждённый статус. Флаг config.discordOAuthEnabled по умолчанию false, до настройки provider.
- Проверены регистрация email/password, поиск/приём сотрудников, отчёты, задачи, жалобы/чат, уведомления, история и копирование содержимого после изменения авторизации.

### Визуальная проверка
- Просмотрены связанные/несвязанные аккаунты на компьютере и телефоне, ошибка настройки, заблокированная отвязка и ограничение демо на телефоне. Нет выхода текста или кнопок за рамки.
- Карточка подтверждённой identity и навигация проверены на ширинах 320–1920 px без горизонтального переполнения.
- Состояния подтверждённой identity для визуальной проверки создавались имитацией API, не реальной авторизацией в Discord. Внешние головы/шрифты здесь недоступны, использовались резервные варианты.

### Настоящее развёртывание ещё требуется
- Приложение Discord, provider/Manual Linking и redirect allowlist в действующем Supabase не настраивались: учётных данных и доступа к проекту нет. Реальный вход в Discord, обмен с действующим Auth-сервером и SQL-отключение legacy RPC необходимо проверить после установки по DISCORD_SETUP.md.
- Отдельная серверная функция не реализовывалась: применяется существующий серверный механизм Supabase Auth. Изменения протокола в будущем могут потребовать обновления REST-адаптера; текущие вызовы сверены с официальным auth-js.
