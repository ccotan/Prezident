# Настоящая привязка Discord — V4.4

Эта версия заменяет ручной контакт **подтверждённой OAuth-привязкой к существующему пользователю Supabase Auth**. Отдельная Edge Function, бот и service_role ключ не нужны. Discord Client Secret вводится **только в настройках Supabase**, никогда в config.js, HTML, репозиторий или переписку.

## 1. Подготовьте общий сайт

- Сайт должен быть опубликован по HTTPS; для локального теста подходит localhost. Автономный HTML показывает интерфейс, но **не привязывает настоящий Discord**.
- Настройте существующую регистрацию/вход по почте: заполните supabaseUrl и публичный supabaseAnonKey в config.js. Не меняйте эти значения на секретный ключ.
- Войдите обычным игроком с подтверждённой почтой. Ник и членство министерства сохраняются: привязка добавляется к тому же Auth user ID.

## 2. Создайте приложение Discord

1. Откройте https://discord.com/developers/applications → New Application.
2. В приложении откройте OAuth2. Найдите Client ID и Client Secret.
3. В Supabase → Authentication → Sign In / Providers → Discord скопируйте **Callback URL**. Обычно это `https://PROJECT_REF.supabase.co/auth/v1/callback` (для custom domain используйте именно URL из панели).
4. В Discord → OAuth2 → Redirects добавьте этот Callback URL **в точности**, затем Save Changes. Это НЕ адрес страницы сайта и не адрес HTML-файла.
5. В Supabase → Authentication → Sign In / Providers → Discord включите provider и укажите Client ID / Client Secret. Сохраните.

Бота создавать/приглашать на сервер Discord не требуется. Используются стандартные scopes `identify email` для провайдера Discord в Supabase. Доступ к сообщениям, списку серверов, ролям и управлению Discord-сервером не запрашивается кодом портала.

## 3. Включите ручную привязку и возврат на сайт

1. В настройках Supabase Authentication включите **Manual Linking / Allow manual linking** (расположение и подпись переключателя могут различаться по версии панели). Простого включения Discord provider недостаточно.
2. В URL Configuration укажите Site URL опубликованного портала.
3. Добавьте в **Redirect URLs** точный адрес портала с `?discord_link=1`. Примеры:
   - `https://example.com/?discord_link=1`
   - для сайта в папке: `https://example.github.io/portal/?discord_link=1`
   - если открывается конкретный файл: `https://example.com/portal/index.html?discord_link=1`
   - локально, отдельно: `http://localhost:8000/?discord_link=1`
4. В config.js установите `discordOAuthEnabled: true`. До завершения настройки значение false оставляет кнопку неактивной, чтобы игрок не попал в неработающую авторизацию.

**Два адреса различаются:** Redirect в Discord — серверный `/auth/v1/callback` из Supabase. Redirect в Supabase — опубликованный портал с `?discord_link=1`.

## 4. Обновите файлы

- Замените файлы сайта версией V4.4, сохранив свои публичные настройки config.js и добавив флаг discordOAuthEnabled.
- Для V4.3 выполните `supabase/upgrade-v4.4.sql`: он отключает старую ручную запись контакта. Старые контакты не удаляются и не становятся подтверждёнными. Новый интерфейс их не использует.
- Для нового проекта `supabase/schema.sql` уже содержит это ограничение. Настоящая привязка хранится в штатных Auth identities Supabase, а не в публичной таблице игроков.
- Для перехода с V4/V4.1/V4.2 схема старого контакта необязательна: upgrade-v4.4.sql безопасно пропускает отсутствующую функцию. Используйте основные миграции своей версии по README.

## 5. Проверьте настоящий сценарий

1. Войдите на портал **по почте** → Личный кабинет → Привязать Discord.
2. Подтвердите разрешение на официальной странице Discord. Вводите пароль Discord только на discord.com.
3. Вернитесь в тот же браузер/вкладку: код OAuth и PKCE verifier обмениваются на сервере Supabase. Новый статус ставится только после проверки identities через `/auth/v1/user`.
4. Убедитесь, что отображаются имя, Discord ID и «Подтверждён через Discord». Проверьте, что Minecraft-ник, глава/министерство и задачи остались прежними.
5. Перезагрузите страницу: связь должна сохраняться. На другом аккаунте она не должна отображаться. «Обновить статус» повторно читает Supabase Auth, а не запрашивает текущее имя у Discord напрямую.
6. Проверьте отмену авторизации, повторную попытку и аккаунт Discord, уже связанный с другим пользователем.
7. Нажмите «Отвязать Discord». Это допускается только при наличии подтверждённой email-identity и ещё одного способа входа; сам профиль портала и его роли не удаляются. При необходимости отозвать разрешение самого приложения сделайте это также в Discord → Authorized Apps.

Не добавляйте отдельный публичный «Вход через Discord» без продуманной первичной регистрации: портал рассчитывает, что сначала создан email-аккаунт с Minecraft-ником, затем к нему привязана identity. Эта версия добавляет именно привязку в кабинете, а не отдельную регистрацию через Discord.

## Защита и хранение

- Начало привязки требует действующую Supabase-сессию; используется `/user/identities/authorize`, а не общий анонимный вход `/authorize`.
- Поток PKCE использует криптографический случайный verifier и SHA-256 challenge. Supabase проверяет серверный OAuth state. Временный verifier хранится в sessionStorage своей вкладки. Запрос считается действительным не более 10 минут; запись удаляется после обработки возврата или выхода из аккаунта, а sessionStorage — при закрытии вкладки.
- При возврате проверяется тот же Auth user ID. Нет подмены игрового профиля и выдачи ролей по данным Discord. Подтверждение не берётся из редактируемого user_metadata или старой таблицы контактов.
- OAuth code очищается из адресной строки при обработке возврата, до загрузки данных кабинета. Для ресурсов страницы добавлена политика no-referrer. Discord provider access/refresh tokens не записываются в localStorage или JSON-снимок. Существующая сессия самого Supabase, как и раньше, хранится в localStorage: защищайте сайт от XSS и не добавляйте непроверенные скрипты.
- Браузер получает только публичный ключ Supabase. Discord Client Secret и обмен с Discord обрабатываются штатным сервером Supabase Auth.

## Если не работает

- **Кнопка неактивна:** откройте общий сайт, войдите в аккаунт и установите config.discordOAuthEnabled=true после настройки provider.
- **Manual Linking disabled:** включите соответствующую настройку Supabase Auth.
- **Неверный redirect_uri:** Callback URL в Discord не совпадает с URL из Supabase.
- **После Discord вернуло на главную:** проверьте точный Redirect URL портала, включая папку, завершающий `/`, имя файла и `?discord_link=1`.
- **Истёк запрос / другая вкладка:** начните заново из текущего личного кабинета, не копируйте callback-ссылку и не меняйте аккаунт в процессе.
- **Discord уже занят:** не пытайтесь обойти ограничение созданием профиля; проверьте, к какому вашему аккаунту он уже привязан.
- **Нельзя отвязать:** подтвердите почту; Supabase запрещает удалять единственный способ входа.

## Что проверено в этой поставке

Локально проверены интерфейс и запросы на имитации Discord/Supabase, PKCE, очистка временных данных, отмена, ошибки, отвязка и сохранение ролей. Настоящее приложение Discord и действующий проект Supabase в этой среде не подключены: реальную авторизацию необходимо проверить после настройки шагов выше.
